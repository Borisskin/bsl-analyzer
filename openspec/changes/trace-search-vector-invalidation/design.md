## Event contract

Reuse `tracing` plus the existing serializer and channel dependencies. Events are structured records, not interpolated messages parsed after the fact. One small shared event vocabulary belongs in `bsl-search`; CLI owns the persistent subscriber layer and writer. Do not introduce a new crate, logging framework, general event bus or audit database.

Common fields: `event_version=1`, UTC time, random process instance ID (existing UUID pattern), PID, monotonic process-local event sequence, operation ID (process ID plus atomic counter), optional parent operation ID, store ID/path, store role, event kind, reason, outcome and count quality. The CLI supplies a process identity; library-only subscribers may use a process-local ID generated from PID/start-time plus monotonic discriminator without a new dependency. Work moved to Rayon, Tokio or threads carries the operation context explicitly or with a correctly propagated tracing span; thread-local ambient state alone is insufficient. IDs contain no lease token, credential or endpoint-derived hash.

Kinds: startup snapshot, decision summary, mutation intent/progress/outcome, hash-reset outcome, embedding pass, artifact lifecycle and journal gap. Outcomes distinguish committed, rolled_back, cancelled, refused, failed, unknown and no_op. A parent cancelled after successful child commits retains those committed child totals. A failed commit or failed rollback must not be labelled confirmed rollback; use unknown when SQLite outcome cannot be established. Drop guards may emit interrupted/unknown, never synthesize success.

Reasons: unchanged, missing_record, hash_changed, hash_cleared, hash_lookup_error, read_error, context_changed, file_deleted, schema_reset, embed_text_version, root_transition, mode_transition, explicit_rebuild, artifact_missing, artifact_stale, artifact_invalid and generation_missing. Record the reason where known; a later empty hash does not prove which earlier process cleared it. Earlier hash-reset records connect by store/file identity and ordering; absent history leaves the initiating reason unknown. Raw errors are replaced with error class/code, never arbitrary Display/Debug text.

### Startup and identity

Capture one read-only SQLite snapshot per logical store open, before this process's migration/ingest work, outside lease and request paths. Put the hook before both unfenced `Store::open` and fenced engine constructor apply callbacks; retries reuse the logical-open context. Use schema inspection to count existing files, `chunks` non-NULL embeddings, legacy overlay rows and overlay value-cache rows independently, with schema/text versions and generation in the same read transaction. Missing database is `absent` with zero rows; unreadable/unsupported schema is explicit unavailable, not zero. Telemetry failure never creates or repairs a database and never blocks its existing open policy.

Include configured roots/mode, executable package/build identity (SHA only when available), normalized database path, and OS file identity where available. Reuse existing file identity patterns. Identity observations bracket the snapshot; changed identity marks it unstable. This describes an observed snapshot, not a lock against external replacements; a read-only snapshot before an overlapping daemon's commit may legitimately differ from a later mutation preimage. Do not copy a snapshot total into a mutation loss count. No attempt to monitor arbitrary external deletion or infer the external actor.

### Counting and transaction attribution

For existing transactions, capture scoped prior non-NULL counts immediately before the destructive statement, in that transaction; use the same selectors as the mutation and count cascaded child rows. Overlapping selectors are counted after previous deletions, never summed from overlapping precomputed sets. Reuse existing scans/returned data where available. Do not equate affected chunks, `ContextRefreshStats.cleared_embeddings` or `embedding_generation` deltas with vector loss. Do not alter UPDATE predicates to skip NULL rows, since that changes generation triggers.

Count separately `sqlite_vectors_removed`, `overlay_vectors_removed`, `overlay_cache_entries_removed`, `hashes_cleared` and `embeddings_written`; memory/HNSW changes are not SQLite loss. Replacement that restores the same row's vector during a preserving table migration has zero logical vector loss. Ordinary non-NULL embedding writes are progress, not invalidation. Successful format migration records hashes cleared and zero immediate vector loss; a later reindex owns its actual loss.

Emit intent into the bounded in-memory stream before destructive work; success only after its existing commit returns success. A batch transaction cancelled at a checkpoint has zero committed losses. Single-statement autocommit and unused public mutation primitives keep existing boundaries: report successful statement/affected rows but `count_quality=unavailable` when an exact preimage cannot be obtained atomically without changing semantics. This exception is confined to the named dormant legacy APIs in the inventory and telemetry read failures; it cannot replace exact counts for normal active transactional paths. Counts with unavailable quality are null, never guessed zero. Hook at the transaction owner prevents wrapper/leaf double counting.

Diagnostic reads must be best-effort and must not introduce a read-to-write upgrade race in a deferred transaction. For replacements/removals, count after the existing first writer statement (file upsert or FTS deletion), before vector deletion. Structural reset already holds an IMMEDIATE transaction. For `apply_context_refresh_batch`, the first statement may itself NULL an embedding: replace only the assignment expression with `embedding = bsl_observe_clear(embedding IS NOT NULL)`. This connection-local scalar function accepts one boolean, increments the active transaction's removed counter when true, and always returns SQL NULL without logging, allocation or an error branch. Its output exactly matches the former NULL assignment; predicates, matched rows, triggers and transaction boundaries stay unchanged. Register through rusqlite's `functions` feature (pure Rust API, existing bundled SQLite), without DETERMINISTIC to prevent constant folding. Reset/discard counters at existing commit/rollback boundaries. Registration failure disables telemetry and retains the original NULL SQL; it never fails search startup. Use this same fixed rule for a direct NULL primitive if instrumented. No preupdate hooks: the installed dependency's preupdate feature would introduce build-time bindgen/libclang solely for logging. Other dormant autocommit APIs keep unavailable preimage counts. This minimal scalar observer is required by exact active-context counts plus unchanged locking; test it against the original SQL under competing writers and rollback.

### Volume, work and failure boundaries

Normal output uses a logical operation envelope and summaries at 128 processed files or one second, plus a final partial summary; at most ten file examples per summary. INFO intent applies to that bounded group before its first mutation; per-file transaction IDs/details are DEBUG-only. Independent one-file operations may have their own envelope. Large single transactions may report uncommitted progress at existing checkpoints; only their final commit contributes loss totals. Summary fields distinguish committed counts, pending intent and unavailable counts. A crash can lose the last partial summary as well as buffered records; absence of a committed record never proves rollback.

The hot path adds bounded counters, allowlisted fields and nonblocking enqueue. It performs no journal filesystem work, waits for no journal lock, and does no full-corpus scan per file/batch. Startup and actual whole-store schema reset may each scan the store once, outside request paths; schema-reset preimage counting stays in its existing writer transaction. Scalar observer counters avoid additional scans where the transaction structure requires them. No source content or vector copying for telemetry. Tests use query/scalar counters and a blocked writer seam instead of a flaky wall-clock performance threshold.

## Persistent sink

Use the existing `dirs::state_dir().or_else(dirs::data_local_dir)` pattern from CLI `mcp/process_record.rs`. Directory is `<state>/bsl-analyzer/vector-journal/<workspace-key>/`; key is BLAKE3 of canonical source directory bytes (or a literal reference-only scope without source), not a secret-derived broker key. Same workspace across process generations shares retention; different databases/cache roots are distinguished inside records. Linux: `$XDG_STATE_HOME` or `$HOME/.local/state`; Windows: `%LOCALAPPDATA%`; macOS: `$HOME/Library/Application Support`. Missing home/state root disables the sink with a diagnostic. Never fall back into `.build`, the repository, runtime tmp or a remote endpoint. Resolve only after existing serve-argument validation, before any search constructor.

Use one process-local worker thread with a bounded 511-record queue plus at most one pending writer record and nonblocking `try_send`; reuse existing crossbeam-channel or std equivalent. Each serialized JSONL record is at most 8 KiB, UTF-8/JSON-safe truncation of allowed string fields marks `truncated=true`; numeric identity/count fields remain intact. Aggregate roots beyond ten entries as count plus digest and bounded examples; DEBUG can stream root details. Queue plus pending record payload is at most 4 MiB plus fixed bookkeeping; encoding uses a fixed 8-KiB bounded buffer and no extra batch copy. This in-process writer is not a new service. The normal diagnostic layer remains as configured; the scoped journal has its own target filter, independent of the broad log level.

Disk layout: eight fixed segment files `0.jsonl` through `7.jsonl`, each at most 4 MiB including its generation header, and one empty permanent `journal.lock` file. Total journal payload is at most 32 MiB and nine files, including concurrent processes. No per-process file proliferation or unbounded temporary files. The worker uses std `try_lock` on `journal.lock` for each complete-record write, retrying contention outside producer paths; selects the highest valid segment generation, appends if a complete record fits, otherwise truncates the next ring slot and writes the next generation header. Generation is logical, not wall-clock mtime. All segment opens/writes/rotation occur under that same lock; close segment handles before unlocking, including on Windows. Never replace/unlink the lock. On missing/corrupt headers use the remaining valid generation; invalid slot content is replaced only on its rotation turn and reported as a gap. Partial final JSONL records after interruption are ignored and truncated to the last complete record under the lock before appending. If repair would require trusting foreign files, disable instead. No index/cache files are opened by the writer.

Unix: newly created private application/journal directories mode 0700; an existing owned application ancestor may be 0755 if not writable by another user, while journal/workspace children stay 0700. Segments/lock 0600, reject symlink/non-regular targets and foreign ownership rather than chmod an unrelated tree. Windows: create a private directory with protected DACL granting the current user (SYSTEM/admin access is outside the confidentiality boundary), reuse the current-user SID/SDDL pattern already present in broker security via a narrow helper; reject reparse targets. Apply ACL at directory creation and inherit into files. Existing unsafe directory/access checks fail closed for logging only. Testing owns platform permission setup; no administrator action is a prerequisite. A library feature already in the workspace may be exposed to the binary for native ACL calls; no shell commands in product code.

Enqueue overflow increments a process-local dropped counter. The next successful writer attempt emits a gap record before data; write/permission/lock errors produce one rate-limited diagnostic per error class per minute on the existing diagnostic channel (outside the scoped sink to avoid recursion). If that channel also fails, observation is unavailable; search still proceeds. Worker retries with bounded queue memory and no producer backpressure; shutdown waits at most two seconds for drain, then records are allowed to be lost. Graceful writer completion flushes OS buffers; no per-record fsync. Persistence means the state-directory files survive ordinary restart/reboot, not power-loss durability. Machine power failure, process crash, saturated queue, disk error and retention eviction can all remove evidence and must be documented. Crash after SQLite commit before journal delivery is inherently ambiguous; no audit-ledger guarantee.
